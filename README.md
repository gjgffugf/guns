# 破绷战场 · BreakBind Battlefield

包名 `xfan.games.gun` · 横屏 · v0.2.0

**技术栈：TypeScript + Three.js + Vite + Capacitor。**
服务器是纯 Node.js（零第三方依赖）。

> 本项目从 Godot 迁移而来。迁移的根本原因：原方案无法在本地做真机验证，
> 每个 bug 都要靠"猜—改—你构建—再报错"的循环推进。换成 Web 技术栈后，
> **所有核心逻辑都能在本地真跑一遍再交付**。

---

## 一、为什么换成 Web 技术栈

| | Godot（旧） | Web + Capacitor（现） |
|---|---|---|
| 语法校验 | 靠自写的正则检查器，**查不出真实编译错误** | `tsc --noEmit`，严格模式，真实类型检查 |
| 逻辑验证 | 下载不到引擎，**无法运行** | 53 个单元测试在 node 里真跑 |
| 界面验证 | 只能靠你构建后反馈 | **Playwright + 真实 Chrome，18 项端到端验证** |
| 坐标系 | CanvasLayer 变换矩阵，布局与命中共 6 类坑 | DOM 布局与 `clientX/Y` 天然同坐标系，**架构上消除** |
| 视频格式 | 仅支持 Ogg Theora | 浏览器原生 mp4 / H.264 |
| 服务器 | Python 标准库 | Node.js，Termux 直接跑 |

## 七、★ 坐标系是怎么彻底解决的

Godot 版本反复出现的"控件看不见 + 点了没反应"，根因是
**布局与命中测试用了两套坐标系**。现在：

- 控件是绝对定位的 DOM 元素，位置由 `src/core/layout.ts` 用 **CSS 像素**算出
- 触摸用 Pointer Events，坐标取 `clientX / clientY`，同样是 **CSS 像素**
- 中间**没有任何变换矩阵**，不需要换算

并且容器 `pointer-events: none`，只有控件本身 `pointer-events: auto`，
隐藏界面统一用 `display: none`（DOM 里它确实不参与命中）。

这三点由浏览器验证脚本的第 9/10/11 项守着：
**每个控件中心点下去必须命中它自己，空白处必须不被吞。**

## 十、手感与联机稳定性（v0.2.6）

### ★ 人物模型朝向与视角不一致

代码里写的是"视角角度 + 180°"，但火柴人模型的**正面是 -z**，
正确换算是取负号。旧公式在 ±90° 附近碰巧正确、在 0° 和 180° 完全反向，
所以表现是"某些方向对、某些方向反"，很难一眼看出规律。

已抽成 `modelYaw()` 纯函数，并用真实的三维四元数在 9 个角度上验证，
另有回归测试证明旧公式确实错。三处调用（自己 / 人机 / 远端玩家）全部修正。

### ★ 摇杆头不跟手

两个原因叠加：

1. 摇杆头的活动半径算大了（行程 + 头的半径 > 底座半径），手指一推它就冲出底座卡住
2. CSS 给位置加了 40ms 过渡，手指一动就有拖影

现在行程 = 底座半径 − 头半径（头恰好贴着底座内缘），并去掉过渡。

### ★ 换弹 / 治疗物挡住子弹

两个按钮整体右移并略微上抬，避开准星正下方与底部血条，且不会撞到跳跃键。
带**布局版本迁移**：老存档只搬这两个控件的位置，你自己调过的大小/透明度保留。

### ★ 多人断线自动重连 5 次

等待间隔逐次拉长（0.8 / 1.5 / 2.5 / 4 / 6 秒）。
区分两种情况：**从没连上** → 退回菜单说明原因；**中途掉线** → 留在游戏里等重连。
主动点退出不会触发重连。

### ★ 服务器列表保存

- 写入后立刻读回校验，真存不进去会在界面上明确警告，而不是假装成功
- 旧版本存的列表自动迁移，不会丢
- 存档损坏 / 含非法条目不会让列表崩掉
- 支持任意多个服务器

### ★ 游戏外延迟不显示

状态页走普通 HTTP，而 App 页面是加密的，属于**混合内容**很可能被拦掉。
新增走游戏同一条通道的探测方式兜底，人数与延迟都能拿到。
为此服务端新增 `query` 指令——只查状态不建号，
否则探测时房间里会闪出一个幽灵玩家，且人数会把自己算进去。

### ★ 服务器列表窗口全屏

手机上原来的窄面板里列表 / 表单 / 按钮组挤在一起，按钮易点歪。

### ★ 切后台帧率跳到 120

统计口径错了：之前记的是系统回调次数，不是真正画出来的画面数。
现在只统计实际画面；切后台时整个循环暂停，回来时重置计时，
避免异常数据把读数带偏。顺带省电。

### ★ 设置里自定义名字

通用页顶部新增「玩家名字」，联机时显示给其他玩家，最长 16 字。

## 十一、修好多人游戏连不上（v0.2.5）

### 根因：Android 默认禁止明文流量

Android 9（API 28）起，系统**默认禁止所有明文流量**，`ws://` 与 `http://`
都会被网络层直接掐掉。Capacitor 6 的 targetSdk 远超 28，于是：

```
ws://192.168.1.10:19000   → 连不上
ws://127.0.0.1:19000      → 一样连不上（loopback 也没有豁免）
```

这正是"手机开服也连不上"的原因：地址没错、服务器在跑，但 App 没发出 TCP 包。

**为什么靠看日志发现不了**：从 JS 侧看，这种拦截与"服务器没开"完全一样 ——
WebSocket 构造函数不抛异常，关闭码恒为 `1006`，拿不到任何原因。

### 修法（三重放行）

| 位置 | 内容 |
|---|---|
| `AndroidManifest.xml` | `android:usesCleartextTraffic="true"` |
| `res/xml/network_security_config.xml` | `<base-config cleartextTrafficPermitted="true"/>` |
| `capacitor.config.ts` | `android.allowMixedContent = true` |

`tools/setup-android.mjs` 有自检，漏任一项 CI 直接失败。

### 新增的排查手段

- **服务器列表 → ★ 诊断**：分别测 WS 与 HTTP 状态页，并给出结论
  （HTTP 通而 WS 不通 = 明文被拦；两者都不通 = 地址错/服务器没开）
- **连不上不再静默进空房间**：现在会等连接结果，失败就退回菜单并说明原因
- **服务端启动时打印可填地址**，照抄即可，不用猜

### 顺带修的

- `wss://` 域名不会再被拼出 `444` 这种不存在的端口
- 服务端日志加 `flush=True`（重定向到文件时也能立刻看到地址）

## 十二、布局 / 贴墙滑行 / 联机 / 绷带调整（v0.2.4）

### 控件布局按截图重排

```
左下  摇杆
右下  两列：外列 开火/开镜/切换武器，内列 跳跃/蹲下/趴下
底部  治疗物（血条左）+ 换弹（血条右）
```
列间距 154px、行距 148px，92px 大按钮之间仍有明显空隙（有测试守着不重叠）。

### 贴着墙不能侧向移动 —— 已修

原因是我之前的扫掠移动用了"某轴一旦被挡就永久停止推进"。
对圆形障碍这是错的：顶着圆走时**沿切线方向本来就该能走**，
永久锁轴把角色钉死在墙上。

现在改成：每小步接受解算后的位置（切线分量自然保留 → 能贴墙滑行），
穿模由 `crossesSolid()` 单独拦（一小步若跨过障碍内部就停止推进）。
因为 `MAX_STEP=0.2` 远小于任何障碍直径，正常移动不会触发。

### 设置页右侧滚动条

每个栏目的内容超出时，右侧出现一条可**长按拖动**的滚动条。
拖动监听挂在 `window` 上（不是滑块自己身上），所以手指移出滑块也照样跟手。

### 绷带与能量饮料

- 破损的绷带：**4 秒**，恢复 **70** 点（原 5 秒 / 40 点）
- 冰冰冰：用完后左上角 **FPS 正下方**显示 `冰冰冰 12.3s` 倒计时

### 多人联机已开放

协议从 UDP 改成 **WebSocket** —— 浏览器 / WebView 里发不出 UDP 包，
只有 WS 能通。服务端同时监听 TCP 19000（WS）、UDP 19000（调试）、TCP 19001（状态页）。

服务端提供两个版本，协议完全一致：

| 文件 | 适用 |
|---|---|
| `server/server.py` | Termux 直接跑（python3 是基础包，不装任何东西）|
| `server/server.js` | 有 Node 的环境 |

**没有任何 AI / 陪练机器人。**

服务器列表支持添加 / 编辑 / 删除，每行显示延迟与 `在线/上限`，
选中后下方四个按钮：连接 / 刷新延迟 / 编辑 / 删除。

### 服务端能放哪些免费平台

见 `server/DEPLOY.md`（摘要）与仓库根目录 `free-hosting.md`（完整调研）。
一句话：**纯 HTTP 免费平台放不了**，因为它们不放行自定义端口的入站流量。

## 十三、治疗物位置 / 多点触控 / 控件尺寸（v0.2.3）

### 治疗物：只有一个，贴在"治疗物"控件上

之前屏幕上出现**两个**治疗控件：
`layout.ts` 里 `heal` 是九宫控件之一（左下），`TouchControls` 画了一个"治疗物"按钮；
HUD 又在屏幕正中单独放了圆形绷带图标 —— 于是绷带跑到了画面中央。

现在合并成一个：

- `TouchControls` 里的 `heal` 只保留**透明命中层**（负责点击判定）
- 视觉由 HUD 绘制，位置直接用 `rectOf('heal', ...)`，与命中层同一个矩形
- 绷带名和数量显示在**圆形按钮上**；三角箭头在按钮上方；展开栏再往上一层
- 在设置里拖动"治疗物"控件，按钮会跟着动

### 多点触控

每根手指按 `pointerId` 独立记账（`held` / `last` / `looking` 三个 Map），

| 组合 | 结果 |
|---|---|
| 摇杆 + 开火 | 边走边打 |
| 开火 + 跳跃 | 边打边跳 |
| 按住开火 + 另一指滑动 | 边打边瞄 |

## 十五、碰撞 / 音效 / 手感（v0.2.1）

### 碰撞

之前**完全没有碰撞**：玩家能走出场外、人机直接穿墙。现在：

| 内容 | 实现 |
|---|---|
| 障碍物实体 | `src/game/collide.ts`，圆柱近似；逐段扫掠，高速也不穿模 |
| 走不出场外 | `clampToBounds` 留出身位半径 |
| 中央高台 | **不**当障碍物（四面是斜坡，由 `groundHeight` 给高度），否则会在坡底被侧面挡住上不去 |
| 沿墙滑行 | 逐段逐轴尝试，顶着墙也能侧向移动，不会卡死 |
| 人机 | 与玩家共用同一套 `step()`，自动获得碰撞 |

### 音效

**WebAudio 实时合成，不需要任何音频文件**
（Godot 版就是吃了"素材没进仓库 → 全程静音"的亏）。

覆盖：枪声 / 空仓 / 换弹 / 命中 / 击杀 / 受伤 / 跳跃 / 落地 / UI 点击。

Android WebView 的 AudioContext 需要用户手势解锁，
已在首次 `pointerdown/touchstart/mousedown` 时自动解锁，
切后台回来也会重新恢复。

### 视角与控件的分工

| 手指动作 | 结果 |
|---|---|
| 滑动摇杆 | **只走路**，不转视角（避免走位时自己转晕） |
| 按住开火 / 跳跃等按钮并滑动 | **同时转视角**（滑动瞄准） |
| 按住开火不动 + 另一根手指滑 | **转视角**（两根手指互不干扰） |
| 空白处滑动 | 转视角 |

这三条由浏览器验证脚本守着，靠 CDP 派发真实多指触摸序列验证。

- 默认灵敏度 0.7 → **1.25**

| 右滑 | 向右转 |
| 左滑 | 向左转 |
| 下滑 | 向下看 |
| 上滑 | 向上看 |

不喜欢纵向方向可在「设置 → 通用 → 反转纵向」切换。

由 `src/game/aim.ts` 的 `applyLook()` 实现（纯函数），
`tests/aim.test.ts` 用「朝向向量在右方向上的投影」来断言，
不是靠肉眼看。

## 十七、全屏 / 无白边 / 隐藏状态栏

三件事分别由三处保证：

| 问题 | 处理位置 |
|---|---|
| 画布不铺满、留白边 | `src/style.css`（100dvh + 安全区）、`session.resize()` 用 canvas 实际 `getBoundingClientRect()` |
| 刘海/挖孔一侧留白 | `tools/setup-android.mjs` 注入 `windowLayoutInDisplayCutoutMode=shortEdges` |
| 状态栏一直显示 | `tools/setup-android.mjs` 在 styles.xml 加全屏项，并在 `MainActivity` 注入沉浸式代码（含 `onWindowFocusChanged` 重新隐藏） |

HUD 顶部元素用 `env(safe-area-inset-*)` 内缩，画布本身仍然铺满到刘海区。
